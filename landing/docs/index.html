Quickstart

Send your first OTP in four steps.

  1. Create an app. Sign up, verify your email, then register an app on the Apps screen. Copy the appId and appSecret now; they are shown only once.
  2. Pick a track. Your 20 free messages work on either. To send to Bangladesh numbers, nothing else is needed. To send worldwide, connect your phone first.
  3. Send a code. Call POST /v5/otp/send with the user's phone number in E.164 format.
  4. Verify it. When the user types the code, call POST /v5/otp/verify.

The base URL is https://[your-api-domain]. All request and response bodies are JSON. Every failure returns { ok, error, code }, so you can branch on code.

Authentication

Send your app's credentials on every request:

X-App-Id: <your app id>
X-App-Secret: <your app secret>

Keep the appSecret on your server. Never ship it in a mobile app or browser code. If it leaks, rotate it before anything else.

rotate it on the Apps screen: confirm this option exists

Send an OTP

POST /v5/otp/send

{ "phone": "+8801XXXXXXXXX" }

Success returns 201:

{ "ok": true, "sessionId": "...", "expiresAt": 1794000000 }
  • phone must be strict E.164: a plus sign, country code and number, with no spaces or dashes.
  • expiresAt is a Unix timestamp in seconds.
  • Each send is charged to your balance at your track's rate. With a zero balance you get 402 insufficient_credits.
  • Sending again too soon returns 429 resend_cooldown; too many sends to one number returns 429 rate_limited.
  • Code length and lifetime apply to every send.

code length and expiry in minutes

Verify a code

POST /v5/otp/verify

{ "phone": "+8801XXXXXXXXX", "otp": "123456" }

Success returns 200:

{ "ok": true, "verified": true }
  • 400 otp_expired: no active session for that number, or its time ran out. Send a new code.
  • 423 otp_locked: too many wrong attempts. Wait retryAfterSec seconds before trying again.
  • 400 invalid_otp_format or invalid_phone: the code or number failed validation.

Check status

GET /v5/otp/status?phone=%2B8801XXXXXXXXX (URL-encode the plus sign as %2B)

{ "ok": true, "status": "pending", "expiresAt": 1794000000,
  "attemptsLeft": 5, "lockedUntil": null, "verifiedAt": null }

status is pending, verified or expired. If the number has never requested a code, you get 404 not_found.

Webhooks

Set a webhook URL on your app and dP Relay will send events to it.

list the event names and show one example JSON body

Every request carries X-DP-Signature, the hex HMAC-SHA256 of the raw request body, keyed with your app's webhook secret. Check it before you parse the JSON, using a timing-safe comparison on the raw bytes:

import crypto from "node:crypto";

function isValid(rawBody, signature, secret) {
  const expected = crypto.createHmac("sha256", secret).update(rawBody).digest("hex");
  const a = Buffer.from(expected);
  const b = Buffer.from(signature || "");
  return a.length === b.length && crypto.timingSafeEqual(a, b);
}

Reply with a 2xx quickly. Failed deliveries are retried.

retry schedule

Rate limits

Two limits protect your users and your deliverability:

CodeLimitWhat to do
rate_limited [max sends per number per app per period] Stop and tell the user to try later
resend_cooldown [seconds between sends to one number] Disable the resend button until the cooldown passes

Credits and billing

These endpoints use the same app headers.

CallPurpose
GET /v5/billing/creditsYour balance in both buckets, with expiry dates
GET /v5/billing/packagesThe packages you can buy right now
POST /v5/billing/credits/request with { "packageCode" }Start a purchase; returns the bKash destination and amount
POST /v5/billing/credits/submit-trx with { "transactionId", "trxId" }Submit the bKash TrxID after you send the money
GET /v5/billing/transactionsStatus of every purchase

After you submit a TrxID, an operator approves it and your balance updates. Remittance purchases have no bKash TrxID, so they are submitted with the method and reference instead (for example a Western Union or Ria MTCN) or matched by amount. Bulk campaigns are launched from the dashboard. See the payment guides for how to send the money.
